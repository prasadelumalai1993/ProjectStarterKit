# Functional Requirements

What the system must actually do. Write these as testable statements ("the system shall...") where you can, not adjectives ("the system should be fast" belongs in non-functional-requirements.md, and even there needs a number).

Group by area/feature. One line per requirement is often enough; expand only where the behavior is genuinely subtle.
